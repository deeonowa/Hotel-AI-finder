# Путёво — AI-агент для путешествий

Прототип для хакатона Островка, трек «О!дин запрос», команда **bisolid**.

Пользователь описывает будущую поездку обычными словами. Агент понимает требования, уточняет только
необходимое, предлагает и сравнивает варианты, проверяет логистику, пересобирает маршрут после изменений
и доводит до имитированного заказа.

**▶ Видеовизитка (5 минут): [смотреть на Google Drive](https://drive.google.com/file/d/1EMSsjNEQtZYHl8NOnNMA176NoQQzIA5w/view?usp=sharing)**

> В демо пять направлений в пяти странах — Сочи, Анталья, Дубай, Пхукет и Тбилиси — с реальными
> отелями и геоданными OpenStreetMap и климатом Open-Meteo. Цены, доступность, билеты и оплата
> синтетические — это явно отмечено в интерфейсе.

## Быстрый запуск

Нужен только [Docker Desktop](https://www.docker.com/products/docker-desktop/) с Docker Compose.
Ключи, аккаунты и отдельная установка базы данных не нужны.

```bash
git clone https://github.com/ostrovok-hackathon-2026/bisolid.git
cd bisolid
docker compose up --build -d
```

После запуска откройте:

- приложение: [http://localhost:8000](http://localhost:8000);
- Swagger API: [http://localhost:8000/docs](http://localhost:8000/docs).

Дальше достаточно `docker compose up -d`. Логи приложения: `docker compose logs -f app`.

Если `8000` занят:

```bash
APP_PORT=8080 docker compose up --build -d
# открыть http://localhost:8080
```

Остановить сервисы: `docker compose down`. Полностью очистить демонстрационные данные:
`docker compose down -v`.

### Рекомендуемый демо-маршрут

1. Введите: «К морю с ребёнком в ноябре на неделю, до 120 тысяч».
2. Выберите один из вариантов; если понадобится, укажите время прибытия вручную.
3. Напишите «на два дня позже» или «дешевле» — агент пересоберёт текущий план.
4. Добавьте отель в корзину, при желании ранний заезд, затем оформите и подтвердите заказ.

Другие страны: «Куда поехать в январе погреться и покупаться? Летим из Москвы вдвоём» — агент сравнит
города по климату, ценам на ваши даты, перелёту и документам; «а давай лучше в Анталью» — пересоберёт
план в другой стране.

«Новая поездка» очищает только текущий диалог в браузере. Чтобы начать демо с пустой БД, выполните
`docker compose down -v` перед запуском.

## Режим агента

По умолчанию агент работает в детерминированном режиме правил — весь путь доступен без API-ключей.
Чтобы подключить LLM к любому OpenAI-совместимому endpoint для более гибкого NLU и объяснений:

```bash
cp .env.example .env
# заполните LLM_BASE_URL, LLM_API_KEY и LLM_MODEL
docker compose up --build
```

**Наш провайдер и модель:** [OpenRouter](https://openrouter.ai), модель `nvidia/nemotron-3.5-super-vl:free`,
«размышления» модели отключены (`LLM_EXTRA_BODY={"reasoning": {"enabled": false}}`, ход ~0.9 с вместо 3.3 с).

Бесплатные модели OpenRouter ограничены по числу запросов в сутки. Когда лимит исчерпан или провайдер
недоступен, агент не падает: ход разбирают правила, а после паузы он снова обращается к модели.

Локальная LLM через Ollama: `docker compose --profile local up --build`. После первого запуска
один раз скачайте модель: `docker compose exec ollama ollama pull qwen2.5:7b-instruct`.

## Локальная разработка

Требования: Python 3.11+, Node.js 20+ и Docker.

```bash
# Открывает Postgres на 127.0.0.1:5432 только для разработки.
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d postgres

python -m venv .venv && source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
python -m trip_agent migrate
python -m trip_agent serve                          # API: http://localhost:8000

cd web && npm ci && npm run dev                     # UI: http://localhost:5173
```

Vite проксирует `/api` на backend `:8000`.

```bash
pytest
docker compose --profile test run --rm --build tests
python eval/run_eval.py
npm --prefix web run typecheck
npm --prefix web run build
npm --prefix web run test:e2e
```

## Что умеет агент

| Этап | Как |
|---|---|
| Понимание | LLM (или правила без ключа) → намерение + атомарные изменения требований; скрытые требования («с ребёнком» → удобно с детьми, короткая дорога) |
| Уточнение | обязателен только вопрос «когда»; остальное предполагается и видно чипсами «я понял так» с правкой в один клик |
| Направления | 5 городов в 5 странах; город и страну понимает из текста («в Турцию», «в Патонг», «из Москвы» ≠ «куда»); город не из каталога («Батуми», «в Сибирь») — честно говорит и предлагает то, что есть; «за границу» / «по России» и «только не Дубай» учитываются во всех предложениях |
| Вдохновение | «куда поехать?» → сравнение городов: море и воздух в месяц поездки, цены на те же даты, перелёт, виза; внутри города — районы с причинами, климатом, ценой «от» и дорогой из аэропорта |
| Документы | за границей — паспорт, виза, страховка, деньги из проверенных данных; предупреждение, если поездка длиннее безвизового срока; не названный пользователем город подтверждается перед покупкой |
| Подбор и сравнение | жёсткие фильтры → скоринг с весами под пользователя → 3 варианта-компромисса; таблица сравнения |
| Объяснение | почему подходит, чем жертвуем, **кому этот отель не подойдёт**, вклад каждого критерия |
| Состыковки | прилёт → трансфер → заселение, ранний заезд / поздний выезд — кнопкой в корзину |
| Пересборка | «на 2 дня позже», «дешевле», «с собакой» → патч к плану и diff; выбранный отель сохраняется, корзина пересчитывается, замена — с причиной |
| Покупка | корзина → **подтверждение всего, что агент предположил** → заказ → имитация оплаты → ранний заезд, напоминание, трансфер после покупки |
| Сам чинит проблемы | ночной прилёт и 2 часа трансфера, нет раннего заезда, «в гору» с ребёнком → агент сам ищет и проверяет замену, предлагает «Заменить / Оставить» |
| Билеты (демо) | после выбора отеля спрашивает, откуда летите; рейсы туда-обратно в цене и корзине (время местное, с разницей поясов); «какие есть рейсы?» → таблицы рейсов с ценой за всех и выбором конкретного рейса; тариф с ручной кладью или с багажом 23 кг; «вылет вечером», «обратно утром»; «без пересадок» → ищет ближайшую дату с прямыми рейсами; 14 городов вылета |
| Другие отели | «предложи другие отели» → новые варианты при тех же условиях, показанные больше не предлагаются |
| Холодное море | просили купаться, а город выбран по умолчанию и вода холодная → «вот где в эти даты тепло» |
| Нет вариантов | честное «нет» + ослабления, для которых заранее посчитано число вариантов |

## Архитектура

**LLM понимает и формулирует, код решает и считает.** LLM превращает текст в намерение и атомарные
изменения требований (белый список полей) и формулирует ответ (числа сверяются с фактами); фильтры,
цены, ранжирование, проверка состыковок и корзина — детерминированный код. Без ключа агент работает
на правилах. Ответ — типизированные UI-блоки, которые может рисовать любой клиент.

```
backend/trip_agent/
  schemas/      общий контракт: требования, патчи, UI-блоки, действия, заказ
  ports.py      интерфейсы: каталог, цены, трансфер, ранжирование, валидатор, LLM, хранилище
  agent/        оркестратор, NLU (LLM + правила), политика вопросов, NLG, вдохновение
  ranking/      фильтры, скоринг, архетипы, объяснения, ослабления
  validation/   состыковки
  pricing/      DEMO-цены (детерминированные)
  catalog/      Location Pack (JSON)
  locations.py  реестр направлений: цены, расписание и ранжирование у каждого города свои
  booking/      корзина, заказ, оплата (имитация)
  api/          FastAPI /api/v1
  container.py  выбор реализаций (замена поставщика — одна строка)
data/locations/<id>/    город: районы, хабы, климат, правила въезда, маршруты, отели и POI (sochi, antalya, dubai, phuket, tbilisi)
scripts/                сборка данных: климат, OSM, фикстуры, OpenAPI
eval/                   сценарии и метрики качества агента
web/                    Vite + React + TS (типы из OpenAPI)
```

## Качество

- `python eval/run_eval.py` — 63 сценария (семьи, пары, животные, горы, невозможный бюджет,
  пересборка, автоисправление, билеты, инъекции, незнакомые формулировки, другие страны и смена города). Проверяется не только
  «дошли до цели», но и **как агент понял запрос** (итоговые требования). Метрики: доля доведённых
  до цели, уточнения, ходы и мс до первой рекомендации, нарушения жёстких требований, ошибки
  состыковок, ошибки интерпретации, падения. Отчёт — `eval/report.md`.
- `python eval/nlu_eval.py [--mode llm]` — понимание запросов на наборах dev / holdout / holdout2.
  Слепой прогон правил на holdout2 сохранён как есть (`eval/nlu_holdout2_blind_rules.md`):
  без LLM на незнакомых формулировках ~0.36 кейсов целиком — поэтому в финале основной режим — LLM.
