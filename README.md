# О!дин запрос — AI-агент поездок

**Ostrovok Hackathon 2026** · трек «О!дин запрос» · команда **bisolid**

Прототип AI-агента для Островка (трек «О!дин запрос»): путешественник пишет **одно сообщение своими
словами**, агент уточняет только необходимое, подбирает и сравнивает отели, объясняет выбор, проверяет
состыковки (прибытие → заселение → трансфер), пересобирает план при изменении условий и доводит до
оформленного (имитированного) заказа.

Локация MVP — **Большой Сочи** (7 районов: море и горы). Архитектура расширяется на любые локации и
реальных поставщиков без изменения агента.

> 1378 реальных отелей Сочи (OpenStreetMap), климат и рельеф (Open-Meteo), дороги (OSRM).
> **Цены, наличие, билеты и оплата — демонстрационные** и помечены в интерфейсе.

## Быстрый старт

```bash
git clone <repo> && cd OstrovokHotel
docker compose up --build
# → http://localhost:8000      (API: http://localhost:8000/docs)
```

Работает **без ключей** — в режиме правил. Чтобы включить LLM, скопируйте `.env.example` в `.env`,
укажите `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` (OpenRouter, Ollama или любой OpenAI-совместимый
endpoint) и перезапустите. Локальная модель: `docker compose --profile local up --build`.

### Разработка

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -e ".[dev]"
pytest                               # тесты
python eval/run_eval.py              # сценарии и метрики качества → eval/report.md
python -m trip_agent chat            # диалог с агентом в терминале
python -m trip_agent serve           # API на :8000
cd web && npm install && npm run dev # UI на :5173
```

## Что умеет агент

| Этап | Как |
|---|---|
| Понимание | LLM (или правила без ключа) → намерение + атомарные изменения требований; скрытые требования («с ребёнком» → удобно с детьми, короткая дорога) |
| Уточнение | обязателен только вопрос «когда»; остальное предполагается и видно чипсами «я понял так» с правкой в один клик |
| Вдохновение | «не знаю куда» → районы с причинами, климатом месяца, ценой «от» и дорогой из аэропорта |
| Подбор и сравнение | жёсткие фильтры → скоринг с весами под пользователя → 3 варианта-компромисса; таблица сравнения |
| Объяснение | почему подходит, чем жертвуем, **кому этот отель не подойдёт**, вклад каждого критерия |
| Состыковки | прилёт → трансфер → заселение, ранний заезд / поздний выезд — кнопкой в корзину |
| Пересборка | «на 2 дня позже», «дешевле», «с собакой» → патч к плану и diff; выбранный отель сохраняется, корзина пересчитывается, замена — с причиной |
| Покупка | корзина → **подтверждение всего, что агент предположил** → заказ → имитация оплаты → ранний заезд, напоминание, трансфер после покупки |
| Сам чинит проблемы | ночной прилёт и 2 часа трансфера, нет раннего заезда, «в гору» с ребёнком → агент сам ищет и проверяет замену, предлагает «Заменить / Оставить» |
| Билеты (демо) | известен город → рейсы/поезда туда-обратно в цене и корзине; «без пересадок» → ищет ближайшую дату с прямыми рейсами |
| Нет вариантов | честное «нет» + ослабления, для которых заранее посчитано число вариантов |

## Архитектура

**LLM понимает и формулирует, код решает и считает.** LLM превращает текст в намерение и атомарные
изменения требований (белый список полей) и формулирует ответ (числа сверяются с фактами); фильтры,
цены, ранжирование, проверка состыковок и корзина — детерминированный код. Без ключа агент работает
на правилах. Ответ — типизированные UI-блоки, которые может рисовать любой клиент.

```
backend/trip_agent/
  schemas/      общий контракт: требования, патчи, UI-блоки, действия, заказ
  ports.py      интерфейсы: каталог, цены, трансфер, ранжирование, валидатор, LLM, хранилище
  agent/        оркестратор, NLU (LLM + правила), политика вопросов, NLG, вдохновение
  ranking/      фильтры, скоринг, архетипы, объяснения, ослабления
  validation/   состыковки
  pricing/      DEMO-цены (детерминированные)
  catalog/      Location Pack (JSON)
  booking/      корзина, заказ, оплата (имитация)
  api/          FastAPI /api/v1
  container.py  выбор реализаций (замена поставщика — одна строка)
data/locations/sochi/   районы, хабы, климат (Open-Meteo), отели и POI
scripts/                сборка данных: климат, OSM, фикстуры, OpenAPI
eval/                   сценарии и метрики качества агента
web/                    Vite + React + TS (типы из OpenAPI)
```

## Качество

- `python eval/run_eval.py` — 44 сценария (семьи, пары, животные, горы, невозможный бюджет,
  пересборка, автоисправление, билеты, инъекции, незнакомые формулировки). Проверяется не только
  «дошли до цели», но и **как агент понял запрос** (итоговые требования). Метрики: доля доведённых
  до цели, уточнения, ходы и мс до первой рекомендации, нарушения жёстких требований, ошибки
  состыковок, ошибки интерпретации, падения. Отчёт — `eval/report.md`.
- `python eval/nlu_eval.py [--mode llm]` — понимание запросов на наборах dev / holdout / holdout2.
  Слепой прогон правил на holdout2 сохранён как есть (`eval/nlu_holdout2_blind_rules.md`):
  без LLM на незнакомых формулировках ~0.36 кейсов целиком — поэтому в финале основной режим — LLM.
